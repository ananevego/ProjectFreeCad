# Текущий план разработки

## Уже выполнено

- Исследованы локальные данные и исходники FreePCB2 **2.428**, ревизия `ver28`.
- Реализован KiCad `.kicad_mod` → `.fpl`: pads, PTH/NPTH, внешние слои,
  origin без сдвига, silk, основные тексты и контуры.
- Дуги и окружности преобразуются в отрезки с заданной точностью.
- Реализованы mask/paste margins и их приоритеты; непредставимое асимметричное
  скругление выдаёт ошибку, неизвестные настройки явно отражаются в отчёте.
- Существующий STL сопоставляется по исходной `.3dshapes` ссылке; повторная
  конвертация 7 225 моделей не нужна и не выполняется.
- Есть контрольный R0805, структурные тесты, JSON-отчёт, строгий режим и
  безопасная замена выходных файлов. Это ещё не GUI-валидация.
- Добавлены реальные PinHeader PTH и MountingHole NPTH; сохранены их `.fpl`.
  Проверен вариант внешних B.* слоёв R0805 (не эталон Flip/3D).
  Исправлен отказ для отключённых padstack flags; Dwgs.User/Cmts.User сохраняются
  в notes с явной потерей семантики слоя. Filled silk SOT-23 пока отвергается.

## P0 — целевые эталоны и валидация

1. При доступной Windows выполнить полный R0805 roundtrip в FreePCB2 2.428:
   выбрать библиотечный footprint для детали, сохранить `.fpc`, редактировать
   footprint выбранной детали и сохранить `.fpl`.
2. Проверить OpenSCAD-экспорт с существующим STL: папку моделей, копирование,
   координаты, единицы, ориентацию, высоту. Не переконвертировать модель.
3. Получить библиотечный эталон УГО и компонент УГО+footprint из Схематора.
   Изучить точные правила pins, имён, связей и электрических типов перед writer.

Разработка footprint-конвертера продолжается на macOS независимо от Windows;
результаты отмечаются как не проверенные в GUI. До получения эталона УГО его
целевой формат не додумывается.

## P1 — завершить единичную конвертацию

1. Проверить в исходниках FreePCB2, можно ли выразить сплошную заливку `fp_poly`
   без подмены её штриховкой. Начать с сохранённого SOT-23; если прямого аналога
   нет, определить проверяемую аппроксимацию с явной диагностикой или сохранить
   отказ. Не удалять его маркер pin 1 молча. Малая выборка PTH/NPTH и apertures
   уже проверяется; команды и ограничения в `SMALL_SAMPLE_VALIDATION.md`.
2. Проверить правила текста: source layer, baseline/центр, скрытие,
   `${REFERENCE}`/`${VALUE}`. Не выдавать literal binding за динамическое поле.
3. По результатам P0 уточнить 3D transforms и NPTH manufacturing behavior.
4. Разделить parser, внутреннюю модель, writer, matcher и отчёты на модули,
   сохранив CLI и совместимый Python entry point; расширять проверочную выборку
   небольшими именованными примерами, без массового прогона.

Результат: задокументированный конвертер одного footprint с понятным отчётом о
поддержке, потерях и непроверенных допущениях.

## P2 — расширение покрытия и связи компонентов

1. Добавить оставшиеся представимые primitives и padstack настройки; для
   непредставимых конструкций сохранять явную диагностику и строгий отказ.
2. Реализовать KiCad symbols → внутреннюю модель, затем целевой writer УГО
   только по подтверждённому библиотечному эталону Схематора.
3. Построить manifest связей symbol → footprint → model и проверку pin mapping.
4. Подготовить переносимый набор моделей и разрешение basename-конфликтов для
   одной `3d_folder`, не изменяя исходные STL/STEP и не создавая их заново.

Результат: проверяемый перенос небольшого набора целых компонентов.

## P3 — пакетная обработка до 20 000 элементов

1. Получить полный набор исходных KiCad libraries и зафиксировать версии.
2. Добавить batch CLI, продолжение после ошибки, deterministic naming,
   журнал/manifest, повторный запуск и отчёт покрытия.
3. Выполнить согласованные малую и среднюю выборки, затем массовую обработку
   после подтверждения корректности в целевых программах.
4. Подготовить руководство, отчёт валидации и поставляемый комплект.

Каталоги моделей используются как существующие исходные артефакты. Массовая
обработка и анализ геометрии в текущих этапах не выполняются.
