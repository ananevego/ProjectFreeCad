# Передача на Windows-проверку

**Состояние на 2026-10-17.** Для первой связанной preview-поставки поддержанного
профиля локальная разработка, полные прогоны и упаковка завершены. Осталась
проверка в FreePCB2 2.428 и Схематоре 1.429. Если она обнаружит новый дефект,
исправление выполняется после получения сохранённых файлов и наблюдений.
Известные потери и отказы перечислены в отчётах; они не считаются проверенными
или успешно преобразованными элементами.
Критерий «рабочего конвертера» и уже выполненная проба STEP → STL описаны в
[отдельном документе](WORKING_CONVERTER_ACCEPTANCE.md).

## Что передать

| Архив | Назначение | SHA256 |
|---|---|---|
| `handoff/native-validation-kit.zip` | Основной комплект: 24 компонента, 5 отдельных FPL, 10 сценариев и автономный checker | `eaa9ae83aa24381f0538e8c7cf6f0765ec7fbc10dee654cdae56ec7b898a8012` |
| `handoff/linked-smoke.zip` | Три компонента из аудированной массовой поставки и их существующие STL | `95e1ee09ab52e1471ff8c7f6ca6b915f7606a29b5242d3613bc6c9463fb7772a` |

Первый архив достаточен для десяти обязательных сценариев. Второй нужен для
контроля нескольких файлов **именно массовой поставки**. Оба архива доступны
непосредственно в Git-репозитории. Полный `linked-components-preview.zip`
(8 210 компонентов, около 1,6 ГБ после распаковки) остаётся отдельным локальным
артефактом и для этой выборочной native-приёмки не нужен. Три пробы не
подтверждают GUI-поведение каждого из 8 210 файлов; структурный аудит всей
партии выполнен отдельно.

До передачи сравните хеши обоих ZIP со значениями выше. На Windows можно
использовать PowerShell:

```powershell
(Get-FileHash .\native-validation-kit.zip -Algorithm SHA256).Hash.ToLower()
(Get-FileHash .\linked-smoke.zip -Algorithm SHA256).Hash.ToLower()
```

## Порядок работы друга

1. Установить/открыть **FreePCB2 2.428**, **Схематор 1.429**, OpenSCAD
   (для проверки платы и STL), независимый просмотрщик Gerber/drill и Python 3.10+.
   Распаковать оба архива целиком в каталоги с короткими латинскими путями.
   Сохранить исходные ZIP без изменений.
2. В каталоге `native-validation-kit` выполнить:

   ```powershell
   py -3 -B verify_kit.py
   py -3 -B verify_kit.py --init-results results/run.json
   ```

   Для приложений указать единицы **MM**. В FreePCB2 задать «Папка для
   Openscad» как полный путь к
   `native-validation-kit/openscad_models/Bundle.3dshapes`.
3. Открыть `protocol.json` и последовательно выполнить все десять сценариев.
   `expected-catalog.json` содержит ожидаемые native records и размеры;
   `report.json` у каждого компонента перечисляет известные потери. Сохранения,
   снимки экрана, Gerber/drill, netlist и native board SCAD складывать только
   в `native-validation-kit/results/`. При различии сохранить **исходный и
   полученный файл**, скриншот, версию приложения, шаги воспроизведения и
   измеренное значение. Не исправлять исходные FPL/CDS вручную.
4. После основного комплекта выполнить `py -3 -B verify.py` из распакованного
   `linked-smoke/` и открыть три пары CDS/FPL из массовой библиотеки.
   Пути ниже относительны к `linked-smoke/`;
   в каждой папке есть `symbol.cds`, `footprint.fpl` и `report.json`:

   | Пример | Папка компонента |
   |---|---|
   | Логика 74AHC1G4210, SOT-353 | `components/c_co_74AHC1G4210_ef8cd97c3be9e234_3a2b925c9c674ef1` |
   | Таймер NE555P, DIP-8 | `components/c_co_NE555P_15fcf8b93918ba0f_1f0fa62e92353295` |
   | МК ATtiny10-TS, SOT-23-6 | `components/c_co_ATtiny10-TS_2203b156e0716ade_8802aadf59722fa3` |

   Для этой библиотеки путь к OpenSCAD-моделям нужно переключить на
   `linked-smoke/openscad_models/Bundle.3dshapes`. Проверить
   загрузку/сохранение, номера выводов и площадок, связь УГО→корпус и
   размещение STL. Сохранить наблюдения в `native-validation-kit/results/`
   с пометкой имени примера.
5. Заполнить `operator`, `versions`, `notes`, `status` и `evidence` в
   `results/run.json`. Для `passed` обязательны заметка и непустой файл
   evidence с SHA256. Для `failed`/`blocked` указать причину. `not_run` честно
   оставить для невыполненного сценария. Проверить запись:

   ```powershell
   py -3 -B verify_kit.py --results results/run.json
   ```

   Exit code 2 означает, что есть `failed`/`blocked`, и не является поводом
   удалять результаты. Checker проверяет целостность файлов и заполнение
   протокола, но не достоверность визуального наблюдения.

Вернуть каталог `native-validation-kit/results/` целиком вместе с
`results/run.json`; при ошибках приложить сохранённые native файлы и указать,
какой именно файл из массовой библиотеки использовался. До разбора этих
результатов статус GUI, netlist, Gerber и физического 3D-совмещения остаётся
**не подтверждён**.

При отдельной передаче полного массового архива его автоматическая проверка
выполняется **при наличии исходного репозитория** командой
`python3 -B -m src.component_converter.mass verify <распакованный каталог>`.
Команда `src.component_converter --verify` во внутреннем `README.txt` относится
к малым bundle-комплектам и для полной массовой библиотеки не подходит.
